# Generator 品質確認（2026-09-29）

## g1 の初回監査方法

`tests/generator-audit.test.ts` で、初級・中級・上級それぞれ16個の固定seedを検証した。seedは空文字、`0`、`1`、`タコ🐙`、`generator-audit:0`〜`generator-audit:11`。本番と同じ既定の探索上限80を使用し、同一入力で2回生成して再現性を確認する。

- 8×8・64セル・8 Region、各Regionの上下左右での連結性
- 正解配置の行・列・Region・隣接制約、初期配置が正解に含まれ最大1匹であること
- 初期配置なしでもComplete Solverによる唯一解が生成済みの解と一致すること
- Logical Solverで完走できること
- 同一seed・同一難易度から同一の盤面・分析結果を得ること
- seedやRegion IDの付け替えを除いた盤面の重複、回転・反転を同一視した形状の数
- 探索上限0で生成した既定盤面との比較と、そのフォールバック自体の妥当性

実行: `npm test -- tests/generator-audit.test.ts`

## 原因調査と g2 の改善

`generator-audit:0`〜`:15` で、中級・上級各80試行のランダム候補をComplete Solverにかけた。各1,280候補はすべて複数解だった。乱数が同じ値を返すのではなく、正解セルから制限なしにRegionを成長させるだけでは、別解を排除しにくいことが主因だった。採用候補がなく、同じcurated盤面の回転・反転へ落ちていた。この観測は上記コーパスに限定する。

`g2` は初級の構築方法を変えず、中級・上級で次を行う。

1. seedから初級の構築方法で、初期配置なしでも唯一解の盤面を作る。
2. 初期配置を外し、正解セル以外の境界セルを隣接Regionへ移す。
3. 連結性・唯一解・定石での解決を検証し、条件を満たす変更だけを採用する。
4. 指定評価に一致したら返す。上限は既定で1,280提案（80×16）とし、未一致でも検証済み・定石で解ける近い評価の盤面を返す。時間制限では打ち切らず、実行環境による再現性の差を避ける。

探索上限0は従来のcurated fallbackを明示的に使う。有限の探索なので指定難易度への一致は保証しない。

旧 `g1` は移動前と同一のソースを保持し、3難易度×3seedの盤面全体SHA-256を固定テストに追加した。コード復元・共有・結果検証では `g1` / `g2` を振り分ける。既存履歴・盤面・問題IDを書き換えない。

## g2 の拡大回帰テスト

初級128seed、中級・上級各64seedを検証する。共通seedは空文字、`0`、`1`、`タコ🐙`、`generator-audit:0`〜`:59`。初級には `generator-audit:easy:0`〜`:63` を追加する。同一入力で2回生成し、初回監査と同じ独立検証を行う。

回帰の合格基準は、回転・反転・Region IDを除いた異なる形状が75%以上、異なる正解配置が50%以上、curated一致が12.5%以下、指定評価への一致が初級95%以上、中級・上級75%以上。完全な非重複や100%の難易度一致を契約とせず、単一盤面へ戻る退行を検出する。性能は中央値・95パーセンタイル・最大生成時間を観測値として出力し、環境依存の時間を合否条件にはしない。

これらは固定コーパス上の回帰基準であり、全seedの多様性や一様分布の証明ではない。
