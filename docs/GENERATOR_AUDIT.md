- 8×8・64セル・8 Region、各Regionの上下左右での連結性
- 正解配置の行・列・Region・隣接制約、初期配置が正解に含まれ最大1匹であること
- 初期配置なしでもComplete Solverによる唯一解が生成済みの解と一致すること
- Logical Solverで完走できること
- 同一seed・同一難易度から同一の盤面・分析結果を得ること
- seedやRegion IDの付け替えを除いた盤面の重複、回転・反転を同一視した形状の数
- 探索上限0で生成した既定盤面との比較と、そのフォールバック自体の妥当性

実行: `npm test -- tests/generator-audit.test.ts`

## 原因調査と g2 の改善

`generator-audit:0`〜`:15` で、中級・上級各80試行のランダム候補をComplete Solverにかけた。各1,280候補はすべて複数解だった。乱数が同じ値を返すのではなく、正解セルから制限なしにRegionを成長させるだけでは、別解を排除しにくいことが主因だった。採用候補がなく、同じcurated盤面の回転・反転へ落ちていた。この観測は上記コーパスに限定する。

`g2` は初級の構築方法を変えず、中級・上級で次を行う。

1. seedから初級の構築方法で、初期配置なしでも唯一解の盤面を作る。
2. 初期配置を外し、正解セル以外の境界セルを隣接Regionへ移す。
3. 連結性・唯一解・定石での解決を検証し、条件を満たす変更だけを採用する。
4. 指定評価に一致したら返す。上限は既定で1,280提案（80×16）とし、未一致でも検証済み・定石で解ける近い評価の盤面を返す。時間制限では打ち切らず、実行環境による再現性の差を避ける。

探索上限0は従来のcurated fallbackを明示的に使う。有限の探索なので指定難易度への一致は保証しない。

旧 `g1` は移動前と同一のソースを保持し、3難易度×3seedの盤面全体SHA-256を固定テストに追加した。コード復元・共有・結果検証では `g1` / `g2` を振り分ける。既存履歴・盤面・問題IDを書き換えない。

回帰の合格基準は、回転・反転・Region IDを除いた異なる形状が75%以上、異なる正解配置が50%以上、curated一致が12.5%以下、指定評価への一致が初級95%以上、中級・上級75%以上。完全な非重複や100%の難易度一致を契約とせず、単一盤面へ戻る退行を検出する。性能は中央値・95パーセンタイル・最大生成時間を観測値として出力し、環境依存の時間を合否条件にはしない。

これらは固定コーパス上の回帰基準であり、全seedの多様性や一様分布の証明ではない。

## g3 の監査（2026-10-11）

`g2` の盤面には 1 マス Region が多く残っていた（上級の 92% に 1 個以上）。`g3` は生成方法を変えてこれを解消する。背景、方針、試作での比較は `NEXT_PHASE.md`「盤面生成の見直し」に、仕様は `DESIGN.md` に記す。

監査テスト（`tests/generator-audit.test.ts`）の対象を `g3` に替え、合格の条件を厳しくした。固定コーパスは初級 128 件、中級と上級が各 64 件の計 256 件。全件で次を確認する。

- 盤面の形と正解が妥当で、Region が連結している。
- 事前設置がなく、Region だけで唯一解になる。
- 対応している定石だけで解け、評価が指定難易度と一致する。`g2` では中級の 3 件が初級評価だったが、`g3` ではこのコーパスで 0 件。
- 1 マス Region は初級がちょうど 1 個、中級と上級は 0 個。2 マス Region は全難易度で 0 個。
- 開始直後に定石なしで置けるタコは、初級がちょうど 1 匹、中級と上級は 0 匹。
- 上級は Region 枯渇を 2 回以上使う。中級は複数 Region の Line 消去を使い、Region 枯渇を使わない。
- Region の大きさと形が制約の中にある（最大 14 マス、縦横比 3 以下、外接する長方形の 4 割以上）。
- 同じ入力から同じ盤面ができる。

形の重複は、回転と反転、Region ID の違いを除いて 256 件すべてが異なる。

この環境での生成時間（監査テスト内の計測）は次のとおり。他のテストも並行実行したデスクトップ環境の観測値で、モバイル性能の保証ではない。

| 難易度 | `g3` の中央値 / p95 / 最大 | `g2` の中央値 / p95 / 最大 |
| ------ | -------------------------- | -------------------------- |
| 初級   | 35 / 180 / 298 ms          | 179 / 775 / 1,366 ms       |
| 中級   | 13 / 55 / 159 ms           | 1,151 / 2,620 / 3,577 ms   |
| 上級   | 21 / 65 / 98 ms            | 308 / 863 / 1,324 ms       |

`g3` の生成器は、計測済みの試作を移植したものである。移植後の実装が試作と同じ seed から同じ盤面を作ることを、8×8 の 180 件と 10×10 の 30 件で確認した。この突き合わせは一時的なスクリプトで行っており、リポジトリのテストには含まれない。以後の同一性は、`tests/generator-version.test.ts` の固定ハッシュ（`g1`、`g2`、`g3` の各 9 件）で守る。

難易度の解析を配列ベースの実装へ置き換えたため、旧版の盤面が変わらないことを別に確認した。置き換えの前後で `g2` の 129 件（3 難易度 × 43 seed）の盤面と解析結果が一致した。これ以前は `g2` の固定ハッシュがなく、`g1` だけが固定されていた。

- 固定コーパスでの確認であり、すべての seed で指定難易度に届くことの証明ではない。届かない seed では、定石で解ける唯一解の盤面のうち条件に最も近いものを返すか、例外になる。
- 2 つの解析実装の同値性は、テストの約 500 盤面での突き合わせであり、証明ではない。
