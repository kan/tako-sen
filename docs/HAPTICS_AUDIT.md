# Firefox Android の触覚フィードバック調査（2026-09-30）

## 結論

利用者の Firefox Android は156。通常のWebアプリが使う `navigator.vibrate()` でこのブラウザを振動させることはできない。アプリの振動パターンや長押しの時間を変えることで解決する問題ではなく、Firefox側の機能無効化と整合する。開発環境へのデプロイ後、利用者がFirefoxの非対応案内とChromeで実際に振動することを確認した。

- [MozillaのAndroid向け無効化告知](https://groups.google.com/a/mozilla.org/g/dev-platform/c/UEZ753bKK1Q)は、以前から呼び出しが実際の振動を起こさない状態だったと説明している。
- [Bug 1900037](https://bugzilla.mozilla.org/show_bug.cgi?id=1900037)は無効化をFirefox129で実施した記録。[Firefox129の開発者向けリリースノート](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/129)にもAPI削除が記載されている。
- [MDN互換性データ](https://github.com/mdn/browser-compat-data/blob/main/api/Navigator.json)には、Android79以降でAPIが存在し、戻り値が `true` でも実際には振動しない状態が記載されている。Android項目と129の削除記録ではAPI露出の記載に差があるため、実機のAPI有無は実測で切り分ける。APIの存在や `true` を「振動対応・振動成功」と表示しない。
- [MDNのAPI説明](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate)では、利用者の操作が必要で、端末の振動設定・マナーモード・DNDの影響も示されている。対応ブラウザでも実際の振動はWebから検出できない。

ブラウザ識別文字列による振り分け、古いprefix付きAPI、ブラウザの安全設定の回避、ネイティブアプリの追加は行わない。

## 実装の確認と変更

従来の `vibrateForFeedback` は `navigator.vibrate` の有無を確認し、Navigatorをreceiverとしたメソッド呼び出しになっていた。APIがない環境で何もしない処理は正しかった。ただし、設定画面は非対応でも振動をオンにでき、非対応理由を表示していなかった。

- 設定画面でAPI有無を判定し、APIがなければ設定とテストボタンを無効化する。保存済みの有効・無効の好みは書き換えない。
- APIがあっても振動の保証にならないことを説明する。
- 「振動を試す（100ms）」はclickハンドラー内で同期的に呼び出す。通常の8〜35msの短い振動が感じにくいケースと、API自体が動かないケースを切り分ける。
- `accepted` / `rejected` / `unavailable` / `disabled` / `failed` を区別し、要求受付を実際の振動成功として表示しない。
- APIの例外がプレイを中断しないようにする。既存の操作別パターン・オフ設定・視覚フィードバックは維持する。

## 自動テスト

`tests/haptics.test.ts` でAPI有無、オフ、true/false、例外、receiver、配列の非破壊性を確認する。`tests/online-ui.test.ts` で非対応案内・設定保持・同期的な100ms要求・結果表示・オフ時の無効化を確認する。これらはブラウザAPIの模擬テストであり、振動モーターの動作を確認したものではない。

## 実機確認

1. 開発URLを再読み込みし、歯車 →「設定・シード・共有」を開く。
2. Firefox Android156でAPI非対応の案内と無効化された設定・テストボタンを確認する。APIが露出している場合はテスト結果と実際の振動の有無を報告する。「要求が受け付けられた」だけでは振動成功と判断しない。
3. 同じ端末のChrome Androidで振動設定をオンにし、100msテストをタップする。端末の振動設定・マナーモード・DNDを確認し、画面の結果と実際に振動したかを別々に確認する。
4. Chromeで100msは振動するが通常操作の振動が感じにくい場合は、×・タコ配置・誤配置・CLEARのどの操作か記録する。パターンの長さはこの実測を見てから調整する。
5. オフにして通常操作で振動しないこと、再読み込み後もオフが維持されることを確認する。Firefoxでも振動なしで盤面の操作・視覚フィードバックが機能することを確認する。

端末の種類・OS・ブラウザの版・表示された結果・実際の振動を分けて記録する。盤面・履歴を消すための全ストレージ削除は不要。

### 利用者による確認結果

Firefoxで振動が無効である旨の案内が出ること、Chromeで実際に振動することを確認済み。利用者が変更を承認し、コミットを指示した。操作別パターンの感じ方やオフ設定の再読み込み後の保持など、個別手順をすべて実機で確認したとは扱わない。
