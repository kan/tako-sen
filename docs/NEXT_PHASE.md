## 基本方針

- 未ログインでも従来どおり問題生成・プレイ・ローカル保存を使える。通信失敗はゲーム進行を止めない。
- 「オンラインプレイ」の第一段階は、同じ問題をリンクで共有し、各自が非同期に解いて結果を比較する機能とする。同時対戦・協力プレイは対象外とする。
- アカウントはオンライン履歴の所有権と端末間同期のために導入する。ローカル匿名IDを認証済みアカウントの証明として扱わない。
- 公開ランキングはローカル順位と別概念とする。ヒントを使うことを失敗として扱わない。
- Coreのパズルロジックは引き続きブラウザ・テストから独立して利用できるようにする。

### 超級：通常プレイ10回ごとの10×10チャレンジ

ステータス: **コンセプトに基づく設計のみ・未実装**。以下の基本仕様と、実装前に確認する詳細案を分けて記す。今回の作業ではコード・データ契約・DBを変更しない。

#### 基本仕様

- デイリーと同じ10×10・10 Region・10匹の高難易度盤面を「超級」として提供する。ルール・対応定石・盤面の品質基準はデイリーに準じ、日付固定や1日1回というデイリー固有の制限は引き継がない。同じ日のデイリー盤面そのものを提供するという意味ではない。
- 超級はデイリーと同様にオンライン・ログイン専用機能とする。未ログイン時はログインへ誘導し、オフラインでは新たな挑戦を開始しない。通常8×8の未ログイン・オフラインプレイは引き続き維持する。
- 超級の問題選択も通常問題と同じ方針とし、超級の公開ランキングに記録があり、本人の完了履歴がない未プレイ盤面のうち、登録人数が最多の盤面を優先する。同数なら無作為に選び、端末内で直近に提示した盤面とローカル完了済みの同一シードも避ける。候補がある場合は確率による新規生成を行わず、候補がなければ新規生成する。取得・検証失敗時の再試行・生成への切替はオンライン・ログイン条件を満たす範囲だけで行い、オフライン開始への抜け道にはしない。
- 初級・中級・上級の通常問題を10回プレイすると、超級へ1回挑戦できる。難易度を切り替えても共通のカウントとする。
- 10回に到達したら「超級に挑戦しますか？」のダイアログを表示する。
- スキップしても挑戦権を失わず、任意のタイミングで1回挑戦できる。保留できる挑戦権は1回分だけとし、保留中の通常プレイは次の10回へ加算しない。超過分の繰り越しや挑戦権の積み増しはしない。
- 画面に「あとX回で超級に挑戦」を表示する。挑戦権の保留中は残り回数ではなく「超級に挑戦できます」と開始導線を表示する。
- 超級の共有シードからの挑戦は、この回数制限の対象外とする。オンライン・ログイン条件は共有経由でも必須だが、挑戦権がなくても遊べ、保留中の挑戦権も消費しない。共有では指定された盤面を開き、登録人数による問題選択で置き換えない。共有による超級プレイ自体は通常問題10回のカウントに含めない。
- ヒント・ショートカットは既存方針を維持し、挑戦権をヒント用の消費アイテムとして扱わない。通常の8×8プレイを強制的に超級へ切り替えない。

#### カウントと挑戦権の状態遷移（詳細案）

「プレイした回数」は、`DESIGN.md` 第19章の既存のプレイ数と揃える案とする。つまり通常問題の試行で初めて `×` またはタコによって盤面が実際に変わった時点を1回と数え、クリア回数とは区別する。この定義と、同一シードへの再挑戦も別試行として数える扱いは実装前に確認する。

| 状態                                   | 通常問題の対象試行が初めて盤面を変更  | 超級への操作                                          |
| -------------------------------------- | ------------------------------------- | ----------------------------------------------------- |
| カウント中（0〜8回）                   | 1回加算する                           | 通常の超級開始導線は利用不可。共有シードは利用可      |
| カウント中（9回）                      | 1回分の挑戦権を獲得し、案内待ちへ移る | 安全な画面遷移時に挑戦確認を表示する                  |
| 挑戦権あり（案内待ち・保留・開始準備） | 加算しない                            | 「挑戦する」で準備へ進む。「あとで」で1回分を保留する |
| 挑戦開始が確定                         | 次のカウントを0回から再開する         | 挑戦権を消費し、その試行を開始する                    |

- 同一 `playId` の連続操作・クリア・一時停止・復元・再読み込みで重複加算しない。READYのOK、未操作で次の問題へ進む操作、ヒント閲覧だけでは数えない。
- デイリー・超級・チュートリアルの試行は加算対象外。通常8×8の共有・シード復元・再挑戦は、上記の通常試行の定義に従って扱う案とする。
- 保留中に遊んだ通常試行を、挑戦権消費後に遡って加算しない。消費後に始まる対象試行から新しく数える。
- 挑戦権を消費するタイミングは、盤面生成・検証・保存に成功し、超級READYのOKで開始を確定した時点とする案。ダイアログへの同意、生成失敗、READYでの取り消しだけでは消費しない。
- 開始済みの超級を再読み込みして続ける場合は同じ試行の再開であり、追加の挑戦権を要求しない。開始後に諦めても消費済みの権利は戻さない案とする。

#### 画面導線とタイマー（詳細案）

- 通常プレイ画面の難易度・問題操作に近い位置へ、控えめな残り回数表示と超級への導線を置く。保留してもメニューを探さず挑戦できるようにする。
- 10回目のプレイ開始時に内部では権利を獲得するが、入力ジェスチャーやプレイ中の推論を遮らない。現在の問題のクリア後、または次の問題へ進む時などの区切りで確認ダイアログを表示する案とする。既存のクリア・ヒント等のダイアログには重ねない。
- ダイアログは「挑戦する」「あとで」を用意し、閉じる・Escape・背景タップも「あとで」と同じ扱いにする。保留後は通常問題を遊ぶたびに自動表示せず、利用者が超級の導線から開始する。
- 案内待ちと案内済みの保留を区別して保存し、再読み込みで同じ案内を繰り返さない。案内前に閉じた場合は、次の安全な区切りで案内する。
- 超級への移動前に、未クリアの通常盤面を置き換えることを明示する。ダイアログを開くだけで現在の盤面を破棄しない。確認中は計時を停止し、キャンセル後の復帰は既存のモーダル・READYの仕様に合わせる。

#### 保存・共有・成績と既存仕様との境界

- 超級のオンライン・ログイン専用条件に合わせ、カウントと挑戦権を別アカウントへ流用しない。カウント、挑戦権、案内状態、重複加算防止情報、開始済み試行を再読み込み後も保持する。保存の正本をサーバーとするかアカウント別の端末保存とするか、未ログイン・オフライン中の通常プレイを加算するかは実装前に確定する。既存履歴を遡って権利に換算せず、導入時は0回から開始する案とする。通信断・セッション失効時の開始済み超級の一時停止・再開方針も定め、進行や消費済み権利を失わせない。

確認事項: プレイ回数の起点（最初の盤面変更かクリアか）、同一シード・通常共有・再挑戦の数え方、未ログイン・オフライン中の通常プレイの加算可否、案内の表示タイミング、権利消費の起点と中断後の扱い、アカウント単位の保存方式・端末間同期と導入時の初期値、保存不可・複数タブ、通信断・セッション失効時の再開、超級ランキングのデータ契約。オンライン・ログイン専用と登録人数の多い未プレイ盤面の優先は確定仕様とし、残る詳細案を確定してから実装へ進む。

完了条件として、少なくとも以下を自動テストと実機確認の対象にする。

- 9回では挑戦不可、10回で1回だけ解放され、残り表示と案内が一致すること。
- 未ログイン・オフラインでは共有経由も含め新しい超級を開始できず、アカウント切替で他人のカウント・挑戦権を利用できないこと。通常8×8のオフラインプレイは維持すること。
- 超級の候補から本人の完了済み・除外対象を避け、登録人数最多を優先し、同数時のみ無作為に選ぶこと。候補なしの場合の新規生成と、共有盤面を候補選択で置き換えないことも検証すること。
- 未操作・再読み込み・同一試行の連続操作では加算されず、対象外モードでも増えないこと。
- スキップ後に権利を保持し、通常問題を何回遊んでも積み増し・繰り越しせず、任意のタイミングで開始できること。
- 開始前の取消・生成失敗で権利を失わず、開始時だけ消費し、再開や同時操作で二重消費・二重開始しないこと。
- 権利消費後は0回から数え直し、保留中のプレイを遡って加算しないこと。
- オンライン・ログイン条件を満たす共有超級は権利の有無に関係なく再現・プレイでき、保留権利や通常カウント、デイリーの挑戦状態を変更しないこと。
- 10×10の唯一解・対応定石での解決・表示・操作・保存復元を検証し、8×8と旧シードに回帰がないこと。
- 通常プレイを遮らず案内し、フォーカス・計時・スキップ後の導線・再読み込み後の表示が整合すること。

### インタラクティブチュートリアルの実装

ステータス: **実装済み・実機確認中**。従来の5ページの説明モーダルを、独立した固定初級盤面で操作を練習する導線に置き換えた。旧版既読でも新チュートリアルの参加確認を一度表示し、最初の長押し対象は青色で点滅させる。最初のタコは自動×なしで置き、ダブルタップを練習してから自動×を選ぶ。通常の盤面・結果・ヒント・計時は変更せず、自動×の選択だけ通常設定へ反映する。実機での操作感とアクセシビリティは引き続き確認する。

今あるチュートリアルのような紙芝居スタイルではなく、実際のゲーム画面に近い盤面で、プレイヤーに操作させながら、1つずつルールと操作法を覚えてもらう

- 最初に「チュートリアルを見ますか」はい/いいえ のモーダルを出す(初プレイ時)
- 盤面を表示(初級レベルの固定盤面)
- 1マス確定リージョンを青い点滅枠で強調して「長押しでタコを置きます」→長押しさせる
- 「タコをダブルタップすると、他のタコを置けない位置に×をまとめて置きます」→ダブルタップさせる
- 「正解のタコを置けたら自動で×を置くこともできます。設定しますか？」→はい/いいえ
- 「この列は○○以外にタコはいません」→スライドで×を置かせる
- 「ここに置くと○○のタコを置けなくなります」→設置不能マスにバツを置かせる
- 「ヒントを押すとヒントが出ます」→ヒントボタンを押させてヒントを出す
- 「あとは自由に進めてみてください」→通常プレイと同様に操作させ、クリアしたらチュートリアル終了のおしらせ

他にレクチャーしたほうが良い要素があれば、同じような形で盛り込む

### 通常問題のランキング参加者を増やす問題採択

ステータス: **ローカル実装・自動テスト済み、開発環境への反映と実機確認待ち**。Cloudflare の開発用 D1 では公開スコア 1,173 件が 1,171 問に分散し、1,170 問は登録者が1人だった。同じ問題で競いやすくするため、「新しい問題」「次の問題へ」では、ログイン中の本人に完了記録がなく、選択難易度の公開初回スコアがある問題を候補とする。登録人数が最多の候補を優先し、同数なら無作為に選ぶ。候補がある場合は確率による新規生成を行わない。端末内で提示済みの盤面とローカルで同じシードをクリアした問題も避ける。

候補取得 API は認証済み本人に問題 ID・シードコード・登録人数だけを最大30件返す。クライアントは候補を再生成して問題 ID を照合し、通信不能・未ログイン・候補なし・検証失敗時には従来どおりクライアント生成へ戻る。既存のプレイ中盤面、シード復元、共有問題、デイリーの採択は変更しない。D1 のスキーマ変更は不要。詳細は `DESIGN.md` と `DATA_CONTRACT.md` を参照する。

## 決定事項と公開前の残課題

1. 認証は Clerk。ゲーム内表示は本人が設定したゲーム名のみとし、氏名・メール・認証 ID は表示しない。
2. 問題 ID と共有スナップショットの形式は `DATA_CONTRACT.md` に定義済み。Generator 更新前に旧版の保持方法を確認する。
3. 過去のローカル履歴の取り込みは第5段階で廃止する。新規クリアだけを自動同期し、`playId` で重複を排除する。
4. プレイ中の盤面は同期しない。端末間で自動統合・上書きを行わない。
5. 名前設定時の明示同意後に初回スコアを自動公開する。個別非公開は設けず、退会で公開記録・ゲーム名を削除する。
6. 新規結果の投稿は1分10件まで。サービス全体の濫用監視、ゲーム名への運用対応、バックアップ、障害時の復旧手順は公開前の残課題。

第5段階の API・DB は承認済み仕様に合わせて更新した。未確認の運用・実機項目を残したままβ公開しない。
