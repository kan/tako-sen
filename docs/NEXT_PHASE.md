# TAKO-SEN — 次フェーズ仕様・着手計画

## 位置付け

初期版の到達点は `DESIGN.md` 第22章の範囲で達成済みとする。本書は次フェーズの仕様と実装順序を管理する。ゲームルールと設計原則の正本は引き続き `DESIGN.md` とし、オンライン機能を理由にオフラインでのプレイ可能性を失わせない。

## 初期版の棚卸し

第22章の必須項目（8×8盤面、Region表示、入力・正誤判定、初期ショートカット、Solver、唯一解を持つ生成、基本ヒント、ローカル保存）は実装済み。ローカル成績、難易度、シード復元、タイマーも実装済み。

以下は初期版の未達ではなく、次フェーズで扱う品質改善とする。

- ポップアップのフォーカス制御とキーボード操作（実装済み。支援技術での確認は継続）
- ヒントの段階的開示、誤った×の絞り込み、×の適用操作（実装・基本動作確認済み）
- Generatorの多様性・難易度分類精度と実機での操作感
- UI操作・保存データの回帰テスト拡充

## 基本方針

- 未ログインでも従来どおり問題生成・プレイ・ローカル保存を使える。通信失敗はゲーム進行を止めない。
- 「オンラインプレイ」の第一段階は、同じ問題をリンクで共有し、各自が非同期に解いて結果を比較する機能とする。同時対戦・協力プレイは対象外とする。
- アカウントはオンライン履歴の所有権と端末間同期のために導入する。ローカル匿名IDを認証済みアカウントの証明として扱わない。
- 公開ランキングはローカル順位と別概念とする。ヒントを使うことを失敗として扱わない。
- Coreのパズルロジックは引き続きブラウザ・テストから独立して利用できるようにする。

ステータス: **基本実装と実機での動作確認を完了**。支援技術での確認と Generator の品質改善は継続する。

ポップアップのフォーカス移動・復帰・Escape対応、段階的ヒント、問題IDと保存データ検証は実装済み。実機での基本動作は確認済み。外付けキーボードや支援技術での確認は未記録のため継続する。

- 問題IDは表示用シードだけに依存させず、Generatorバージョンと盤面の不変な署名を含めて定義する。旧版シードの復元を維持する方法を、Generator変更前に決める。
- `playId` は試行ごとに一意とし、結果送信の冪等キーに使う。保存データの版、検証、破損データ時の扱いを明確にする。
- 既存のローカル履歴は利用者の明示操作で取り込み、同じ `playId` は重複登録しない。取り込み後もローカルの控えを直ちに削除しない。

問題ID、旧版の扱い、移行・同期競合の契約は [`DATA_CONTRACT.md`](./DATA_CONTRACT.md) に記す。端末確認の手順は [`DEVICE_CHECKLIST.md`](./DEVICE_CHECKLIST.md) に記す。

完了条件: 既存のオフライン機能に回帰がなく、問題ID・履歴移行・同期競合の仕様とテストケースが定まる。

### 2. アカウントと履歴同期

認証方法を比較して採用し、ログイン・ログアウト・セッション失効・退会を実装する。複数端末から自分の履歴を読めるようにする。保存先の候補は Workers API と D1 とし、認証方式は実装前に決定する。

ステータス: **開発環境で基本動作を確認済み**。認証基盤に Clerk を採用し、開発用 D1 に完了履歴テーブルを作成した。明示的なローカル履歴取り込み、認証済み本人の履歴取得、`playId` による重複・競合判定、退会 API と `user.deleted` webhook を実装した。公開した開発用 Worker で未認証 API の `401`、許可外 Origin の `403`、署名付き webhook の `200` を確認した。同一アカウントの2端末間で履歴を同期でき、別アカウントからは見えないことも確認した。Clerk Dashboard の `user.deleted` テスト配信は `200`。使い捨てアカウントの退会では、D1 の履歴が削除され、別アカウントの履歴と端末のローカル履歴は残った。キー未設定では認証機能を表示せず、従来のオフラインプレイを維持する。本番環境・支援技術・セッション失効時の実機確認は別途行う。

フロントエンドの環境変数 `VITE_CLERK_PUBLISHABLE_KEY` には公開可能キーだけを設定する。秘密鍵を `VITE_` 付きの環境変数に入れない。ローカル API の設定方法は [`README.md`](../README.md) に記す。Clerk のログイン状態とローカル匿名 `userId` は独立して扱い、ローカル履歴は自動送信しない。

開発用公開の環境設定と別端末確認の手順は [`DEPLOY_DEV.md`](./DEPLOY_DEV.md) に記す。開発用 URL は <https://tako-sen.kan-fushihara.workers.dev>。

- サーバーは認証済み主体とローカル由来の `userId` を分離する。クライアントから送られた `userId` だけで所有権を認めない。
- 完了記録はサーバーで入力検証し、本人のみが非公開履歴を取得できるようにする。
- 通信失敗時はローカルのプレイを続け、再送時には `playId` で重複排除する。複数端末の「プレイ中」盤面については、自動上書きを避ける競合方針を先に定める。
- 退会時は Clerk アカウントと D1 の履歴を削除し、端末のローカル履歴は残す。第4段階では公開ランキングの記録と匿名名も削除する。

完了条件: 未ログイン・オフラインでもプレイ可能で、ログイン後に既存履歴を安全に移行し、別端末で確認できる。

### 3. 非同期オンラインプレイ

問題共有リンクから、同一の盤面を開いて挑戦できるようにする。リンク先の問題が旧版Generatorでも再現できることを保証するか、再現できない版は明示的に扱う。

ステータス: **開発環境で基本動作を確認済み**。作成者のみログイン必須、受け取る側は未ログインでも開ける。D1 に正解配置を含まない盤面スナップショットを保存し、公開リンクから唯一解をローカル復元する基本実装とテストを追加した。開発用 D1 のマイグレーションと Worker の再デプロイを完了し、未認証の作成拒否、不正・未登録 ID の応答を確認した。利用者が未ログインの別端末で同じシードと盤面を開け、クリア後にログインして履歴を取り込めることを確認した。2回目の取り込みでは登録済みと判定され、重複しなかった。公開 GET 応答に `solution` がないことも確認した。両端末でのクリア結果の比較表示は未実装で、公開ランキングは第4段階で扱う。

完了条件: 2端末で同じ盤面を解け、結果の送信失敗・再送でも挑戦が重複しない。

### 4. 履歴・ランキングのリッチ化

自分の履歴に問題別ベスト、期間・難易度別集計、推移、絞り込みを追加する。その後、同一問題の公開ランキングを追加する。公開範囲はオプトインとし、表示名・非表示・削除を設計する。

ステータス: **個人履歴と公開ランキングの基本動作を開発環境で確認済み。β公開前の UX 再設計が必要**。取得済みのオンライン履歴（直近500件）から、問題 ID 単位の自己ベスト、期間・難易度別の集計、最近のクリア時間の推移、シード・問題 ID による絞り込みを計算・表示する。利用者が表示と絞り込みの動作を確認した。2026-09-27に、記録の公開と別アカウントからのランキング閲覧も確認した。公開取り消し・退会後のランキング削除など、残る実機確認は `DEPLOY_DEV.md` を参照する。

公開ランキングは記録ごとの明示参加、自動生成の匿名名、同じ問題で各参加者の公開済みベスト1件を表示する。時間・ヒント数・ミス数で比較し、同成績は同順位。個別または全件の公開取り消しができ、退会時は公開記録と匿名名も削除する。既存履歴は自動公開しない。公開変更は1分10回までに制限し、取り消しは制限しない。詳細は `DATA_CONTRACT.md` を参照する。

- ランキング対象の同一性は問題IDで判定し、選択難易度と実際の評価を混同しない。
- クライアント申告の時間・ミス・ヒント数は完全には検証できない。初期の公開順位は参考記録として示し、送信頻度制限・入力検証・重複防止を設ける。競技性の高い順位は検証方式を別途設計する。

完了条件: 自分の成長と同一問題での比較が分かり、公開を望まない利用者の結果は表示されない。

#### 5. オンライン同期・ランキングの UX 再設計

ステータス: **開発環境で基本動作確認済み。支援技術等の確認は継続**（2026-09-29）。開発用 D1 へ第4マイグレーションを適用し、Worker と静的画面を再デプロイした。静的画面・新バンドルの `200`、未認証 API の `401`、許可外 Origin の `403`、ランキング取得の `200` を確認した。以下の新仕様は、第2〜4段階に記載した旧仕様の手動取り込み・個別公開・匿名名・公開ベストを置き換える。

現行の「ローカル履歴の取り込み」「オンライン履歴の更新」「記録ごとの公開」「同じ問題を開いてランキング更新」という分断された操作は複雑で、利用者からユーザーフレンドリーではないとの指摘があった。機能が動作することと、β公開できる使いやすさは別とし、現行導線のままβ公開しない。

- クリアから端末間同期、同じ問題の結果比較までを一続きの体験として再設計する。
- 同期状態・公開状態・ランキングへの参加方法を、説明を読まなくても把握できるようにする。
- 自動同期と自動公開は別の概念として説明し、ゲーム名の設定時に両方のルールへ明示同意を得る。同意前の結果は送信しない。
- オフラインプレイ、再送時の重複防止、望まない公開を防ぐ原則は維持する。

承認済み仕様

- ログインの情報はあくまで個人の同定に使用し、取得したID,Email等はゲーム内には露出しない
- 最初のログイン時にゲームで使う名前を決める → ゲーム内にはその名前を表示
- ログイン中はプレイ履歴は自動的にオンラインに同期される
- 公開ランキングにも自動反映され、特定のランキングだけ非公開にする機能は付けない
- ゲームの性質上、ランキングへの反映は初回スコアのみ
- 退会であらゆるランキングから履歴を消す
- 上記のルールは最初の名前付けの際に説明を入れる
- 過去履歴の取り込みは廃止する。未ログイン時や名前・同意の設定前のクリアも、後からログインして自動送信しない。既存のオンライン履歴は本人の個人履歴として残し、ランキングには再公開しない。
- 初回スコアは、認証済みアカウント・問題 ID ごとに、サーバーへ最初に登録されたクリアとする。クリア日時が古い記録の後着や再挑戦で置き換えない。再挑戦も個人履歴には同期する。
- 通信失敗時は、同意済みアカウントに紐付けた未送信キューを端末へ保存し、再接続・同じアカウントでの再ログイン時に再送する。別アカウントのキューは送信しない。プレイ中の盤面は同期しない。
- ゲーム名は見た目の2〜20文字（書記素単位）、文字・数字・絵文字・空白・ハイフン・下線を使用できる。国旗・肌色・ZWJ による組み合わせ絵文字も扱い、表示ではカラー絵文字用フォントを使う。他アカウントと重複する名前は使えない。名前の変更は、不正防止の観点から利用者の判断で一旦保留する（2026-09-29）。
- マイグレーション `0004_automatic_ranking.sql` で旧公開状態を非公開に戻す。既存の自動匿名名は新ルールへの同意・名前設定として扱わない。旧公開・取り消し API は廃止する。
- 同期後に履歴と現在の問題のランキングを自動再取得する。新規登録はアカウントごとに1分10件までとし、同内容の再送は制限しない。
- ランキングは画面表示・画面へ戻ったとき・ランキング欄を開いたとき・クリア・同期完了時に自動更新し、手動更新ボタンは設けない。古い問題の応答で現在の問題の表示を上書きしない。
- 名前設定・同期状態・オンライン履歴・ログアウト・退会は、ヘッダーの名前ボタンから開くアカウントモーダルにまとめる。モーダルを閉じても同期処理は続ける。Escape・閉じるボタン・背景タップで閉じ、キーボードのフォーカスは名前ボタンへ戻す。

2026-09-28 の開発版について、利用者は基本動作を「ほぼ OK」と確認した。2026-09-29 に上記のランキング自動更新・名前欄のモーダル化・絵文字名対応だけを追加調整し、承認を得て開発環境へ再デプロイした。利用者が追加調整の動作を確認した。第6・7段階の本格的な UX 再設計は今回に含めない。支援技術・セッション失効などの継続確認は `DEPLOY_DEV.md` を参照する。

完了条件: 初めて使う人が補足説明なしで名前・同意の設定、同期、ランキング閲覧、退会による公開削除を行え、公開範囲を誤解しないことを実機で確認する。端末確認の新手順は `DEPLOY_DEV.md` を参照する。第6・7段階は未着手。

## 決定事項と公開前の残課題

1. 認証は Clerk。ゲーム内表示は本人が設定したゲーム名のみとし、氏名・メール・認証 ID は表示しない。
2. 問題 ID と共有スナップショットの形式は `DATA_CONTRACT.md` に定義済み。Generator 更新前に旧版の保持方法を確認する。
3. 過去のローカル履歴の取り込みは第5段階で廃止する。新規クリアだけを自動同期し、`playId` で重複を排除する。
4. プレイ中の盤面は同期しない。端末間で自動統合・上書きを行わない。
5. 名前設定時の明示同意後に初回スコアを自動公開する。個別非公開は設けず、退会で公開記録・ゲーム名を削除する。
6. 新規結果の投稿は1分10件まで。サービス全体の濫用監視、ゲーム名への運用対応、バックアップ、障害時の復旧手順は公開前の残課題。

第5段階の API・DB は承認済み仕様に合わせて更新した。未確認の運用・実機項目を残したままβ公開しない。
